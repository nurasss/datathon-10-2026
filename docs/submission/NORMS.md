## 3. Принцип сопоставления правил с видео

Цепочка ровно такая и не короче:

1. **Наблюдение** (то, что видит CV-пайплайн): человек в кадре, зоны рабочего места, статичные
   предметы, состояния по времени. Наблюдение описывает **только видимое**: «зона рабочего места не
   занята», «на столе появился статичный предмет», «дверца сейфа распахнута».
2. **Гипотеза** (предположение, а не вывод): событие-кандидат с меткой времени и кадрами-доказательствами.
   Формулировки намеренно осторожные — «предполагаемое оставление…», «может указывать на…».
3. **Норма из закрытого реестра**: гипотезе сопоставляется правило из реестра приложения
   (`forte-vision/packages/rules/rules/registry.json`), причём **в боевую выдачу попадают только записи
   со `status=approved`**. Текст пункта и ссылка на акт **копируются** из реестра.

Ключевое ограничение: **модель не генерирует нормативные ссылки**. Ни один номер пункта, ни одна цитата
не порождаются генеративно — они берутся из заранее выверенного реестра; если подходящего правила нет,
результат не выдаётся вообще (а не «придумывается» ближайшая норма). То же зафиксировано в политике
реестра приложения: *«Нормативные ссылки никогда не генерируются моделью: текст пункта скопирован из
официальной публикации и сверен с двумя независимыми публикациями»*.

Что из этого следует практически:

* Тип нарушения без утверждённого правила **не может** появиться в ответе `done` — это by design, а не
  баг. Реестр приложения выверен куратором (v3.0-curator, все 11 правил `status=approved`), поэтому
  нормативная ссылка есть у всех 8 типов; фактическая детектируемость типов в текущей версии — в
  `TYPES.md` §0 и §9.
* Если тип отсутствует и в черновом реестре норм (`registry_draft.json`) — это `rule_id PENDING`:
  ссылку выдавать нельзя, пока куратор не внесёт и не выверит норму.
* Формулировка результата — **подсказка проверяющему** («предполагаемое…»), а не юридическая
  квалификация: документально ни факт обслуживания, ни принадлежность денег, ни полномочия вошедшего
  по видео не устанавливаются (см. колонку «Что по видео установить нельзя»).

## 4. Чего в черновом реестре нет (честный список `not_found`)

* Отдельного запрета приёма пищи/напитков на рабочем месте — **в №231 и №14 не найден**; допустимо
  использовать только `KZ-NB231-P12-1` (хранение личных вещей), с оговоркой.
* Постановление №231 п.75 (вход в кладовую/сейфовую комнату) — касается **кладовой/сейфовой комнаты**,
  а не кассы; к помещению из видео не применять.

Для этих случаев правило прежнее: норма не выдумывается, тип помечается как не имеющий нормы в реестре.
