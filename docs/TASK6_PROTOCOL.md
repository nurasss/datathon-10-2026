# Задача 6 — протокол гибрида

Рабочая ветка — `feat/core`, каталог `fv-core`. Полный прогон назначен на
**2026-10-18 06:00:00 +05:00**, местное время машины; срок отчёта — 06:30.
Регистрация таймера: `artifacts/task6/schedule.json`. Пока нет завершённого
`full_run.json`, результаты replay не являются итоговой оценкой зрения.

## Слои

- **A:** существующие типизированные правила. Их признаки, устойчивость и
  нормативные соответствия не ослабляются. Colab-YOLOX явно выключен в контексте.
- **B:** `detect_ev01`, `detect_ev02` и `DeskWatcher` из baseline `5f4ad60`.
  `events.py` и `deskobjects.py` побайтово совпадают с исходным коммитом;
  копии сохранены в `artifacts/task6/provenance/baseline_*.py`.
  Новый адаптер `vision/hybrid.py` принимает **уже вычисленные** наблюдения и
  назначения треков, не вызывает детектор и не создаёт новый трекер.
  Рабочая зона B восстанавливает исходную grid-логику baseline и её fallback;
  зона A при этом не меняется. Сохранён выбор primary по времени в зоне.
- B использует доступные кадры существующей сетки наблюдений: плотные внутри
  окон, редкие вне окон. Новых окон/проходов нейросети или чтения видео для B нет.
  Маленькие серые кадры сохраняются в памяти непосредственно при существующих
  вызовах detect; из них DeskWatcher строит фон и маски по тем же детекциям.
- В описании B статичный предмет **не объявляется доказанными деньгами**,
  другой трек — доказанным клиентом, а обслуживание — документально незавершённым.
  Сохраняются дословная цитата и `cannot_infer` проверенного реестра.

## Маппинг и приоритет

| Исходный сигнал | Новый код | Норма |
|---|---|---|
| EV01 | LEAVE_DURING_SERVICE — «Уход с рабочего места во время обслуживания клиента» | KZ-NB231-P22 |
| EV02 | LEAVE_VALUABLES | KZ-NB231-P20-2 |

P22 уже находилась в утверждённом JSON-реестре. Добавлено типизированное
соответствие в `TAXONOMY`; нормативный текст не переписывался.

Любое событие A, пересекающее окно составного условия B (от `raw.peak`
до конца эпизода), подавляет этот B. Более раннее появление самого предмета
ещё не является окном «предмет без присмотра».
Отсутствие A в другом окне того же ролика не запрещает B. B никогда не вытесняет A
при ограничении числа событий. Сохранены объединение соседних однотипных событий
и исходная опция baseline: не дублировать один EV01-эпизод вложенным EV02.
Эта операция не является новым визуальным фильтром.

Единственное новое подавление FP B: **только EV01**, если наблюдённый непрерывный
`lockscreen` длительностью не менее двух секунд содержит момент начала отсутствия.
Поздняя блокировка, `None`, `off` или краткий lockscreen не заменяют этот критерий.
Для EV02 такой фильтр не применяется. Никаких списков имён роликов, правил по
аннотациям или дополнительных визуальных эвристик в рабочем B нет.

Для времени используется исходный `raw.peak`: это первое выполнение составного
условия, не середина интервала. У EV02 это начало незанятости, у EV01 — уход во
время обслуживания либо приход клиента к уже незанятому месту. Исходные интервалы
и вариант baseline сохраняются в meta/trace. Для начала записи предыдущего кадра
не существует: evidence ограничивается границами видео.

## Replay и сохранность измерений

`scripts/replay_hybrid.py` не вызывает модель. Подготовка NPZ-кэша читает исходные
пиксели с времён сохранённого trace; затем варианты читают только JSON/NPZ.
Для кадров плотного прохода воспроизводится JPEG95-кэш перед уменьшением;
для coarse/reused используются исходные пиксели. Это не повторный инференс.

Ранние пробы на coarse-only сетке и последующая observed-grid проба сохраняются
отдельно в `artifacts/task6/replay_*/`. Неудачные пробы сериализации не удалены:
логи находятся в `artifacts/task6/variants/`. Результаты replay не подменяют
полный evaluate; при смене coarse fps они не предсказывают изменения окон A.

`scripts/run_task6_at_0600.py` регистрирует один таймер и эксклюзивный маркер
запуска; не переносит пропущенный слот на следующую дату и не повторяет ошибку.
Полный вывод: `artifacts/task6/final/stdout.log`.

Три строки сравнения вычисляет `scripts/report_task6.py` только из файлов:
оригинальный baseline `forte-vision/artifacts/eval/20261017_174122`, задача 4,
гибрид. Копия original baseline — `artifacts/task6/baseline_original/`.

`type_hit` — доля video-level TP, где есть хотя бы один код из замороженного
`events.csv`. Старые EV01/EV02 отображаются строго по таблице выше. Новые
положительные метки LEAVE_DURING_SERVICE задним числом не добавляются;
поэтому бинарный TP может не иметь правильного типа. Это явно отражается
в сравнении, а не маскируется расширением ground truth.

Сцена, аннотации, чужие worktree и общий `.venv` в этой итерации не редактируются.
Установленных новых пакетов нет. Артефакты игнорируются Git и передаются отдельно.
