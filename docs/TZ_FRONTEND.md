# ТЗ Frontend — ForteVision

Версия: 1.0 · Дата: 17.10.2026

Связанный документ: [ТЗ Backend](./TZ_BACKEND.md).

## 1. Основание и приоритет требований

Источники: `Кейс_ForteBank.docx`, `ForteBank_MASTER_TZ_v2.0_Единое.docx`, проверка локального проекта и метаданных датасета.

- **[К]** — требование исходного кейса, обязательно для конкурса.
- **[П]** — проектное решение, обязательное для реализации по этому ТЗ, но не отдельное требование организатора.
- **[У]** — вопрос, требующий подтверждения; не считать решённым.

При расхождениях первичен исходный кейс. Настоящий документ задаёт целевое состояние, а не подтверждает готовность существующего кода.

## 2. Цель и границы ответственности

**[К]** Реализовать интерфейс, в котором проверяющий загружает новое видео `.mov`, наблюдает обработку и получает проверяемый результат без запуска скриптов.

Frontend отвечает за:

- выбор файла, предварительную проверку и отправку;
- отображение загрузки, обработки, ошибок и результата;
- просмотр видео, событий, таймкодов, доказательных кадров и нормативных источников;
- интеграцию с браузерным API backend;
- доступность и адаптивность.

Frontend **не отвечает** за детекцию, классификацию, вычисление вердикта, извлечение кадров, генерацию объяснений и выбор правовых норм. Эти данные предоставляет backend; клиент не придумывает и не исправляет их самостоятельно.

Не входят: регистрация, профили, история проверок, экспорт, пакетная загрузка, мобильное приложение, live CCTV, лица, звук, интеграция с АБИС.

## 3. Технологии и ограничения

- **[П]** Интерфейс на русском языке.
- **[П]** Допустим текущий HTML/JS-интерфейс FastAPI либо React + TypeScript + Vite. Переписывание только ради стека не требуется; выбор фиксируется до разработки.
- **[П]** Desktop от 1280 px и мобильный экран 375 px, без горизонтальной прокрутки основного содержимого.
- **[П]** Скрипты, стили, шрифты и иконки поставляются локально. Нет сторонней аналитики, CDN-зависимостей и облачных AI SDK.
- **[К]** Видео, кадры и их описания не передаются внешним AI-сервисам.
- **[П]** Файлы, кадры и ключи не сохраняются в localStorage, IndexedDB, service-worker cache или клиентской телеметрии.
- **[П]** Имя файла, описания и названия норм выводятся как текст, без небезопасного HTML.

## 4. Пользовательский сценарий

1. Открыть публичный адрес сервиса.
2. При необходимости открыть доступ вводом выданного ключа.
3. Выбрать или перетащить один `.mov`.
4. Увидеть имя, размер и результат предварительной проверки.
5. Нажать «Анализировать».
6. Дождаться загрузки и серверной обработки.
7. Получить вердикт и список событий либо корректный пустой результат.
8. Открыть событие, перейти к таймкоду, изучить кадры, объяснение и источник.
9. Начать новую проверку.

## 5. Экраны и состояния

### 5.1. Доступ

**[П]** Минимальный экран ввода ключа, без регистрации и управления пользователями. Backend обменивает введённый ключ на защищённую браузерную сессию. Не встраивать ключ жюри в JS, HTML или `VITE_*`.

Предусмотреть: неверный ключ, недоступность сервера, истечение сессии, выход. После успешного входа очистить значение поля. Не выводить ключ в URL или консоль.

### 5.2. Загрузка

Обязательные элементы:

- название сервиса и пояснение «Анализ видимых признаков возможных нарушений. Не является юридическим заключением»;
- выбор одного файла и drag-and-drop;
- поддерживаемый формат `.mov`;
- имя и размер выбранного файла;
- удаление/замена файла до отправки;
- кнопка «Анализировать», недоступная без валидного выбора;
- понятная ошибка рядом с областью загрузки.

**[П]** Размер сверяется с конфигурацией backend, а не с жёстко заданными 29 МБ. Проверка расширения на клиенте предварительная: окончательное решение принимает сервер.

Повторное нажатие не должно создавать несколько запросов. На время отправки блокировать повторную отправку. Прогресс загрузки показывать только при наличии измеренного значения; иначе использовать индикатор без процента.

Отмена до отправки обязательна. Прерывание HTTP-загрузки не обозначать как отмену уже созданной серверной задачи: endpoint отмены анализа в MVP отсутствует.

### 5.3. Обработка

Показывать `job_id`, текущую стадию, индикатор ожидания и пояснение о предельном времени обработки.

Внутренние стадии: `queued`, `probe`, `decode`, `reasoning`, `evidence`, `finalize`, `finished`. Человеческие подписи: «Ожидание», «Проверка видео», «Анализ», «Подготовка кадров», «Формирование результата», «Готово».

- **[К]** Публичные статусы анализа: только `processing`, `done`, `failed`.
- **[П]** Нельзя рисовать фиктивный процент или показывать «Готово» до `done`.
- **[П]** Polling примерно раз в 2 секунды, без перекрывающихся запросов. При сетевых ошибках — ограниченный backoff, затем явная ошибка связи с возможностью продолжить опрос.
- **[П]** Останавливать polling при terminal status, уходе со страницы и размонтировании компонента.
- **[П]** Перезагрузка страницы задачи восстанавливает её состояние по `job_id`, а не создаёт новую задачу.
- **[П]** По превышении 300 секунд показать предупреждение о нарушенном сроке; не подменять серверный результат. Разрешено продолжить получение фактического статуса.

### 5.4. Результат

Верхний блок: безопасное имя файла, длительность при наличии, итоговый статус, вердикт, количество событий.

Отображение вердиктов:

| API | Текст интерфейса |
|---|---|
| `violation` | «Обнаружены признаки возможных нарушений» |
| `no_violation` | «Признаки возможных нарушений не обнаружены» |

Не использовать формулировки «виновен», «доказано нарушение», «операция законна».

Для каждого события:

- тип и таймкод в формате `мм:сс.д`;
- описание наблюдаемого действия;
- пояснение, почему событие требует проверки;
- 1–3 JPEG из ответа;
- название нормативного документа, пункт/раздел при наличии и ссылка;
- явное разделение наблюдения и возможной нормативной интерпретации.

Если backend не предоставляет отдельные части объяснения, вывести полное `description` без самостоятельного смыслового разбиения и домыслов.

Видео размещается рядом со списком на desktop и над списком на мобильном экране. Нажатие таймкода или карточки выполняет seek и выделяет выбранное событие. Автовоспроизведение не требуется. Недоступность плеера не скрывает события и JPEG.

**[П]** Входной MOV не гарантированно воспроизводится во всех браузерах. Frontend использует предоставленный backend `video_url` с совместимой копией, если она необходима. Сам клиент не перекодирует видео.

### 5.5. Пустой результат и ошибки

Обязательные состояния:

- `done` + `no_violation` + пустой массив — нормальное завершение, не ошибка;
- `failed` — анализ не выполнен, без положительного или отрицательного вердикта;
- неизвестный/истёкший `job_id`;
- неподдерживаемый, пустой, повреждённый или слишком большой файл;
- заполненная очередь;
- нет соединения, сервер недоступен, сессия истекла;
- недоступно отдельное изображение или видео;
- некорректный ответ backend.

Показывать понятное действие: «Выбрать другой файл», «Повторить запрос статуса», «Начать новую проверку», «Войти снова». Не повторять POST автоматически после неоднозначного сетевого сбоя: это может создать дубликат задачи.

Не показывать stack trace, файловые пути сервера, секреты и внутренние сообщения модели.

## 6. Интеграционный контракт

### 6.1. API жюри: эталон результата [К]

Frontend не вызывает API жюри со встроенным общим ключом. Его схема служит общей моделью результата:

```json
{
  "job_id": "opaque-id",
  "status": "done",
  "verdict": "no_violation",
  "violations": []
}
```

При положительном результате каждый элемент `violations` содержит:

| Поле | Тип / ограничение |
|---|---|
| `type` | непустая строка |
| `timecode_sec` | число секунд от начала видео |
| `description` | объяснение и нормативная привязка |
| `evidence_frames` | 1–3 объекта |
| `evidence_frames[].timestamp_sec` | секунды исходного кадра |
| `evidence_frames[].image_base64` | JPEG base64, без data URI префикса |

Для отображения изображения клиент может сформировать `data:image/jpeg;base64,...`. Отсутствие evidence у события — ошибка контракта, а не повод самостоятельно удалить событие и изменить вердикт.

### 6.2. Браузерный API [П]

Same-origin запросы, session cookie, без ключа в bundle:

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/ui/api/session` | JSON `{ "api_key": "..." }`, создание сессии |
| DELETE | `/ui/api/session` | завершение сессии |
| GET | `/ui/api/config` | `{ "allowed_extensions": [".mov"], "max_upload_bytes": 100000000, "deadline_sec": 300 }` — размер здесь пример |
| POST | `/ui/api/analyze` | multipart `file`, ответ `{ "job_id": "..." }` |
| GET | `/ui/api/jobs/{job_id}` | результат и UI-метаданные |
| GET | `/ui/api/jobs/{job_id}/video` | защищённое видео с поддержкой Range |

Формат браузерного GET:

```json
{
  "job": {
    "job_id": "opaque-id",
    "status": "processing"
  },
  "meta": {
    "filename": "clip.mov",
    "duration_sec": null,
    "stage": "queued",
    "progress": null,
    "video_url": null,
    "event_details": [],
    "error_code": null,
    "error_message": null
  }
}
```

`job` строго соответствует публичной схеме. В `done` он содержит вердикт и события. `meta.progress` — число 0..1 либо `null`; длительность и URL могут быть `null`, если ещё недоступны.

Каждый элемент `meta.event_details`: `violation_index` — индекс в `job.violations`, `observation` — строка либо `null`, `rule_reference` — объект `{ "title": "...", "paragraph": null, "url": "https://..." }`. Данные подготавливает backend. Для `failed` заполняются безопасные `meta.error_code` и `meta.error_message`.

Cookie отправляется с запросами. Backend проверяет Origin для изменяющих запросов. Ссылки на нормы открываются по явному действию пользователя с `noopener noreferrer`; разрешены только HTTP(S) URL, лучше HTTPS.

### 6.3. Параллельная разработка

До готовности backend использовать локальные fixtures браузерного API: processing, no_violation, одно событие, несколько событий, failed, 401, 404/410, 413, 429, 503, потеря связи, испорченный JSON.

Fixtures доказательных изображений — синтетические либо разрешённые тестовые материалы. Не добавлять приватные видео и кадры в публичный репозиторий.

## 7. Доступность и качество

- Выбор файла, отправка, карточки и таймкоды доступны с клавиатуры.
- Видимый focus, подписи полей, кнопки имеют понятные имена.
- Стадии и ошибки доступны через `aria-live` без объявления каждого polling-ответа.
- Статус передаётся не только цветом.
- Alt для evidence: «Кадр на 44,2 с»; время также выводится текстом.
- Базовый контраст текста не ниже WCAG AA.
- На 375 px кнопки и объяснения не перекрывают друг друга.
- Не логировать payload с base64, описаниями тестовых видео и ключами.

## 8. Приёмочные тесты

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| FE-01 | Выбор и замена MOV | Корректное имя/размер, одна активная загрузка |
| FE-02 | Неверное расширение / oversized | Понятный отказ до отправки, серверные ошибки также обработаны |
| FE-03 | Успешная загрузка | Один POST, показан job_id, запущен polling |
| FE-04 | Processing → done | Состояние обновлено без перезагрузки |
| FE-05 | Отрицательный результат | Правильный текст, нет карточек событий |
| FE-06 | Одно / несколько событий | Все события, времена, JPEG и нормы показаны |
| FE-07 | Нажатие таймкода | Плеер переходит к нужной секунде |
| FE-08 | Failed / 401 / 404 / 410 / 429 / 503 | Нет ложного вердикта, есть понятное действие |
| FE-09 | Потеря сети | Нет бесконечных перекрывающихся запросов и автоматического повторного POST |
| FE-10 | Перезагрузка страницы задачи | Восстановление GET без повторной загрузки |
| FE-11 | Keyboard / 375 px / 1280 px | Основной сценарий доступен |
| FE-12 | Privacy / XSS | Нет внешней отправки материалов, встроенного ключа и исполнения текста из API |
| FE-13 | Невалидный результат / сломанное evidence | Показана ошибка, клиент не меняет вердикт |

## 9. Definition of Done и поставка

Frontend принят, если:

1. FE-01–FE-13 пройдены; есть команды и фактические результаты тестов.
2. Полный сценарий работает с реальным backend, а не только с fixtures.
3. Интерфейс доступен по публичному адресу и проверен в актуальных Chrome и Safari; воспроизведение видео проверено отдельно.
4. Есть инструкция запуска/сборки, конфигурация API и описание известных ограничений.
5. Нет секретов, сторонних AI-вызовов и приватных датасетов в клиентской поставке.

Передача: исходный код, fixtures, интеграционные/E2E-тесты, инструкция и список ограничений. Готовность UI не считается доказательством качества CV-модели или выполнения общего лимита 300 секунд.
