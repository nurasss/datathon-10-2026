# Forte Vision — контроль кассовой дисциплины по видео

Решение кейса ForteBank, Datathon 26.

Сервис принимает видеозапись работы кассира (`.mov`), локально анализирует её и сообщает, есть ли визуально наблюдаемые признаки возможного нарушения кассовой дисциплины. Для каждого найденного события показывает тип, таймкод, 1–3 кадра-доказательства, описание увиденного и ссылку на открытый нормативный акт РК.

Результат — подсказка для проверяющего, а не юридическое или дисциплинарное заключение.

> **Статус:** в разработке. Разделы, помеченные *(план)*, ещё не реализованы.

## Принципы

- **Полностью локально.** Все модели работают внутри сервиса. Видео, кадры и их описания не передаются облачным AI-сервисам. После загрузки весов интернет для анализа не нужен.
- **Только визуальный анализ.** Звук не используется, лица не распознаются и не идентифицируются.
- **Без домыслов.** Сервис не делает выводов о том, чего не видно на записи: проводки, сверки, содержимое документов, полномочия.
- **Нормы не генерируются.** Ссылки на нормативные акты берутся из проверенного вручную реестра, а не создаются моделью.
- **Лицензии.** Используются только компоненты и веса с лицензиями, разрешающими коммерческое использование (Apache-2.0 / MIT / BSD).

## Структура репозитория

| Путь | Что внутри |
|---|---|
| `web/` | Веб-интерфейс (Next.js): загрузка видео, статус, результат |
| `forte-vision/` *(план)* | Backend: API (FastAPI), очередь задач, видеопайплайн, реестр норм |

## API

Доступ по ключу в заголовке `X-API-Key`. Запросы без верного ключа отклоняются (`401`). Обработка асинхронная, в два шага.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/analyze` | Загрузить видео `.mov` (поле `file`), в ответ — `job_id` |
| `GET` | `/api/v1/jobs/{job_id}` | Статус (`processing`, `done`, `failed`) и результат |

```bash
curl -X POST https://<адрес>/api/v1/analyze \
     -H "X-API-Key: <ключ>" -F "file=@video.mov"

curl https://<адрес>/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

Ответ после завершения:

```json
{
  "job_id": "3f2a9c1e",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Название типа нарушения",
      "timecode_sec": 44.2,
      "description": "Что видно на видео и почему это может быть нарушением",
      "evidence_frames": [
        { "timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..." }
      ]
    }
  ]
}
```

- `verdict` — `violation` или `no_violation`. При `no_violation` массив `violations` пустой.
- `timecode_sec`, `timestamp_sec` — секунды от начала видео.
- `evidence_frames` — 1–3 настоящих кадра из загруженного видео, JPEG в base64 без префикса `data:`.
- Ошибка обработки возвращается как `failed`, а не как `no_violation`.
- Целевое время обработки — до 5 минут на видео.

## Архитектура *(план)*

```
.mov ─► FFmpeg (декодирование, выборка кадров)
     ─► детектор людей и предметов (YOLOX, ONNX Runtime, CPU)
     ─► трекинг (ByteTrack) + роли: кассир / клиент / посторонний
     ─► состояния: сейф открыт/закрыт, ценности на столе
     ─► временные правила ─► реестр норм ─► кадры-доказательства ─► JSON
```

Вместо обучения большой модели на небольшом датасете используются предобученные детекторы, дообученные на нескольких специфичных классах, и проверяемые правила поверх них.

## Нормативные источники *(план)*

Только открытые акты Республики Казахстан (НБРК, [adilet.zan.kz](https://adilet.zan.kz)). Для каждого типа нарушения будут указаны документ, пункт, наблюдаемый признак и то, что по видео установить нельзя.

## Запуск

### Frontend

```bash
cd web
npm install
npm run dev
```

Откроется на `http://localhost:3000`.

### Backend *(план)*

Инструкция появится вместе с кодом в `forte-vision/`.

## Данные

Обучающие видео и разметка организатора **не хранятся в репозитории** и используются только в рамках хакатона. Тестовые видео жюри не используются для обучения и никуда не передаются.

## Ограничения

Список распознаваемых типов нарушений, известные случаи ошибок и результаты оценки будут добавлены по итогам тестирования.
