# ForteVision · ForteBank Datathon 26

Локальный CPU-анализ `.mov`: FastAPI + SQLite + отдельный процесс OpenCV/NanoDet.
Без облачных AI API, распознавания лиц и анализа звука. Детекция EV01/EV02
сохранена без изменения алгоритмов и порогов; это признаки для проверки человеком.

## Запуск на этом Mac

```bash
cd /Users/nuras/Desktop/datathon/forte-vision
# Уже созданное .venv можно использовать без переустановки.
python3.12 -m venv .venv
.venv/bin/python -m pip install -r apps/api/requirements.txt
# ffprobe/ffmpeg рекомендованы для проверки контейнера (brew install ffmpeg).

# .env уже создан при локальной проверке, содержит случайные ключи, игнорируется Git.
# На чистой машине: cp .env.example .env и заменить ключи случайными значениями.
set -a
source .env
set +a
scripts/run_server.sh
```

Открыть <http://localhost:8000>. Порт **8000**, **1 uvicorn worker**,
один процесс анализа одновременно. Скрипт работает независимо от текущего каталога.
Ключ жюри задаётся только через `FV_API_KEYS` (список через запятую),
не печатается и не попадает в HTML/JS. Отдельный `FV_UI_KEY` защищает UI через
подписанную HttpOnly-cookie; пустой `FV_UI_KEY` делает `/ui/*` публичным.
Для публичного туннеля рекомендуется непустой отдельный UI-ключ и HTTPS.
Не отключать Mac и его питание; туннель настраивается отдельно.

## Контракт

```bash
# После source .env:
curl -sS -H "X-API-Key: ${FV_API_KEYS%%,*}" \
  -F 'file=@/Users/nuras/Desktop/datathon/data_raw/open/videos/Х-20.mov' \
  http://localhost:8000/api/v1/analyze
# {"job_id":"..."}, HTTP 202 — без ожидания анализа

curl -sS -H "X-API-Key: ${FV_API_KEYS%%,*}" \
  http://localhost:8000/api/v1/jobs/JOB_ID
```

- `processing` → `done` или `failed`. Неизвестный id: 404; неверный/отсутствующий ключ: 401.
- При `done` только `job_id`, `status`, `verdict`, `violations` по контракту.
  `no_violation` ⇔ пустой список; у нарушения 1–3 настоящих JPEG в plain base64.
  Обе формы `done`, JPEG и таймкоды проверяются до публикации результата.
- Только расширение `.mov` (регистр не важен); прочее: 415. Пустой файл: 422.
  Нераспознанный/недекодируемый файл: `failed`, без вердикта.
- Лимит файла **100 MiB (104857600 байт)**; выше: 413. Поток multipart также
  ограничен до лимита файла + 64 KiB служебных данных, даже без Content-Length.
- POST ждёт только загрузку/запись файла; проверка и анализ выполняются в процессе.
  В очередь попадают только полностью записанные файлы.
- Watchdog считает **280 с с принятия файла, включая очередь**, а не с начала анализа.
  Истёкшие задачи становятся `failed` (проверка каждые 0,1 с и на GET);
  процесс/его группа завершаются. Поздний результат не перезаписывает `failed`.
  После рестарта незавершённый активный анализ становится `failed`.
- Очередь: максимум 8 принятых задач, иначе 429. На слабом Mac лучше подавать последовательно.
- Данные локально в `data/`, удаление завершённых задач через 72 часа (при простое worker).
  Ошибка/пропажа evidence → `failed`, никогда не подмена на `no_violation`.

OpenAPI: <http://localhost:8000/api/docs>. UI: загрузка, автообновление статуса,
вердикт, кликабельные таймкоды, video Range-запросы, кадры, описание и нормативная ссылка.

## Тесты и воспроизводимый замер

```bash
.venv/bin/python -m pytest -q

# В другом терминале, при работающем сервере:
set -a
source .env
set +a
.venv/bin/python scripts/acceptance.py \
  --videos /Users/nuras/Desktop/datathon/data_raw/open/videos
sysctl -n machdep.cpu.brand_string hw.ncpu hw.memsize
```

`acceptance.py` выполняет настоящие `curl` для AT-01…AT-04, затем последовательно
самый короткий, верхний медианный (22-й из 42 по длительности) и самый длинный ролики.
Время: от начала POST до первого наблюдённого `done`, опрос каждые 0,2 с.
Для каждого evidence JPEG проверяется побайтовое совпадение с повторно извлечённым
и закодированным кадром исходного загруженного видео. Ключи в выводе замаскированы,
base64 сокращён до 40 символов. Полные ответы и замеры — `artifacts/acceptance/`
(не в Git). Проверочный отчёт — `docs/TASK1_REPORT.md`.

## Структура и ограничения

- `apps/api/app`: публичный контракт, загрузка, UI, хранилище, watchdog и subprocess.
- `packages/vision`: исходная детекция людей/событий, извлечение кадров; веса локальные.
- `packages/rules`: исходный реестр норм; выдаются только правила `approved`.
- `scripts/dev_*`: инструменты разработки, **не используются** API и не читают labels
  при анализе загруженного видео. Обучение/подбор порогов в этой задаче не выполнялись.
- `infra`: необязательный Docker (`docker compose -f infra/docker-compose.yml up --build`);
  основная проверенная конфигурация — нативный запуск на Mac, Docker не тестировался.
- `docs/DEPENDENCIES.md`: полный список установленного окружения, лицензии и SHA256 весов.

Нормативный реестр сохранён из baseline: его юридическая актуальность заново не проверялась.
Автоматические зоны и эвристики EV01/EV02 могут ошибаться, точность на 42 роликах не измерялась.
Демонстрационный режим — не многопользовательская production-система; владельцы задач
не разделены между UI-сессиями. Не публиковать UI без ключа, если видео конфиденциальны.
