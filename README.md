# Forte Vision — контроль кассовой дисциплины по видео

Решение кейса ForteBank, Datathon 26.

Сервис принимает видеозапись работы кассира (`.mov`), локально анализирует её и сообщает, есть ли визуально наблюдаемые признаки возможного нарушения кассовой дисциплины. Для каждого события — тип, таймкод, 1–3 кадра-доказательства, описание увиденного и дословная ссылка на открытый нормативный акт РК.

Результат — подсказка для проверяющего, а не юридическое или дисциплинарное заключение.

## Принципы

- **Полностью локально.** Все модели работают внутри сервиса на CPU. Видео, кадры и описания не передаются облачным AI-сервисам.
- **Только визуальный анализ.** Звук не используется, лица не распознаются.
- **Без домыслов.** Сервис не делает выводов о том, чего не видно: проводки, документы, полномочия.
- **Нормы не генерируются.** Ссылки берутся из реестра, проверенного вручную по текстам на adilet.zan.kz.
- **Лицензии** допускают коммерческое использование (Apache-2.0 / MIT / BSD).

## Как устроено

```
.mov ─► FFmpeg ─► NanoDet-Plus (люди и предметы, ONNX Runtime CPU)
     ─► трекинг людей и роли (кассир / клиент / посторонний)
     ─► состояние сцены (экран ноутбука, предметы на столе, дверь) — классическое CV
     ─► типизированные правила по времени ─► реестр норм ─► кадры-доказательства ─► JSON
```

Единственная нейросеть — NanoDet-Plus-m-1.5x 416 (COCO, Apache-2.0, OpenCV Zoo). Обработка ролика — 5–35 с; 5 параллельных роликов через публичный адрес — до 122 с при лимите 300 с.

## Распознаваемые события

| Тип | Норма |
|---|---|
| Уход с рабочего места без блокировки компьютера | Требования АРРФР № 53 от 03.04.2026, п. 71 пп. 9 |
| Уход с рабочего места с оставлением ценностей на столе | Постановление НБ РК № 231, п. 20 ч. 2 |
| Посторонний в кассовом помещении | Постановление НБ РК № 14, п. 16 пп. 1, п. 8 |
| Дверь кассы оставлена открытой | Постановление НБ РК № 14, п. 16 пп. 1 |

## Качество и ограничения (честно)

На 40 обучающих роликах: **найдено 11 из 21 нарушения, ложных срабатываний 0 из 19 чистых роликов**, тип верен в 10 из 11 случаев, медианная ошибка таймкода 1,4 с. Правила настраивались на этих же роликах — отдельного отложенного набора не было, поэтому оценка оптимистична.

- Ручной пересчёт денег, личные вещи и использование телефона в текущей версии не обнаруживаются.
- Сигналы стола и двери зависят от ракурса камеры; на незнакомом ракурсе они могут молчать. События по людям (уход, вход, посторонний) устойчивее.
- Подробно — [`docs/submission/TYPES.md`](https://github.com/nurasss/datathon-10-2026/blob/backend/docs/submission/TYPES.md).

## API

Доступ по ключу в заголовке `X-API-Key`. Обработка асинхронная.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/analyze` | Загрузить видео `.mov` (поле `file`), в ответ — `job_id` |
| `GET` | `/api/v1/jobs/{job_id}` | Статус (`processing`, `done`, `failed`) и результат |

```bash
curl -X POST https://<адрес>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
curl https://<адрес>/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

## Данные

Обучающие видео и разметка организатора в репозитории не хранятся и используются только в рамках хакатона. Тестовые видео жюри не используются для обучения и никуда не передаются.
