# Оформление существующего интерфейса ForteVision

## Назначение и границы

Работа выполняется поверх ветки `frontend`, исходный коммит `fca13f3`. Цель — оформить существующий сценарий, сохранив его поведение. Визуальный ориентир: предоставленный командой макет с тёмно-синей шапкой, светлым фоном и белыми карточками.

Обработчики выбора файла, отправки и polling остаются в `app/page.tsx`. Компоненты оформления принимают данные и callbacks. Они не обращаются к API, не вычисляют вердикт, не выбирают нормы и не модифицируют входные данные.

Бэкенд, инфраструктура, модели, реестр норм, `api.ts`, `mock.ts`, зависимости и настройки сборки не изменены. `Violation` импортируется только как TypeScript-тип и не подключает API в runtime.

## Что оформлено

| Существующее состояние | Отображение |
|---|---|
| Файл не выбран | Заголовок, выбор файла, пояснение процесса, кнопка анализа |
| Файл выбран | Имя и размер, возможность открыть тот же выбор файла заново |
| Статус ещё не получен | Ожидание статуса, идентификатор задачи |
| `pending` | Индикатор ожидания без процента и выдуманных стадий |
| `done` + `violation` | Осторожная формулировка результата и полный список переданных событий |
| `done` + `no_violation` | Отрицательный результат без утверждения о законности операции |
| `error` | Ошибка отдельно от отрицательного вердикта |

Таймкод форматируется в `мм:сс.д`, остаётся обычным текстом. Переход к нему в плеере не обещается: плеера в текущем Next.js нет. Описание показывается целиком, без автоматического разделения на факты и правовые утверждения. Названия и описания выводятся средствами React как текст.

Нет неработающих кнопок входа, выхода, повторной проверки, переключения событий или вкладок. Область выбора не подписана как drag-and-drop: такой обработчик отсутствует.

## Дизайн

- Фон `#f4f6fa`, текст `#18253e`, шапка и основная кнопка `#14233f`, синий акцент `#2e68c3`.
- Белые карточки, тонкие границы, умеренные тени. Предупреждение о возможном событии выделено тёплым цветом, ошибка отделена от нормального результата.
- Системный стек Arial / Helvetica / sans-serif. Загрузка Geist при сборке удалена из оформления.
- Адаптивная сетка: основная форма и пояснение на desktop; один столбец на узком экране.
- Видимый focus, доступный с клавиатуры file input, подпись поля, skip-link, текстовые статусы, отсутствие зависимости только от цвета.
- При `prefers-reduced-motion: reduce` вращение индикатора отключено.

## Соответствие кейсу

Основание: исходный кейс ForteBank, разделы 4–5, 7, 10 и FAQ. Дизайн не означает выполнение всех требований конкурса.

| Требование | Текущее положение |
|---|---|
| Загрузка видео, статус, результат | Существующая демонстрационная цепочка оформлена; настоящий API ещё не подключён |
| Тип, таймкод, описание каждого события | Показываются из полученных данных |
| Реальные кадры-доказательства | В текущем Next.js не отображаются; отдельная задача интеграции |
| Правило и нормативный источник | Отдельной структуры отображения пока нет; полный `description` сохранён |
| Вывод как подсказка человеку | Формулировки результата и пояснение соответствуют этой границе |
| Лимит 5 минут | Указан как требование, а не как измеренная гарантия; новый таймер не добавлен |
| Публичный API и авторизация | Ответственность бэкенда и будущей интеграции |

### Что согласовать с разработчиком API

1. Next.js использует `pending/done/error`, сервер — `processing/done/failed`. Переход согласовать отдельным PR вместе с polling и обработкой ошибок.
2. `api.ts` не отправляет ключ; способ аутентификации выбрать до подключения к серверу. Не размещать общий ключ в клиентском bundle.
3. В `backend` есть `/api/v1/jobs/{job_id}/details`, `/video` и отдельный встроенный HTML-интерфейс. Это не тот же набор `/ui/api/...`, который предлагался в ТЗ. Опираться на реальный контракт.
4. Плеер, кадры, нормы, повторная проверка, защита от повторной отправки и восстановление после обновления страницы — отдельное функциональное изменение.
5. Видеометод сервера возвращает MOV. Наличие URL не доказывает совместимость кодека с браузером.

### Работа аналитика

Проверить названия категорий и осторожность объяснений; подготовить нормативы для серверного реестра. При приёмке проверить факты и таймкоды по исходному видео внутри разрешённого локального контура. Для макетов не переносить реальные описания сцен в облачные инструменты.

## Проверки 17 октября 2026 года

До изменений общий lint обнаруживал три ошибки и два предупреждения; сборка не могла получить Google Fonts. После оформления изменённые файлы проходят ESLint, production-сборка проходит на Node.js 24.19.0. Общий lint сохраняет одну исходную ошибку и одно предупреждение в неизменённом `mock.ts`.

Локальная проверка Playwright в Microsoft Edge:

- `handleFile`, `handleUpload`, `useEffect` сопоставлены через TypeScript AST: совпадают после нормализации переносов строк. `api.ts` и `mock.ts` совпадают с исходным коммитом.
- На настоящей странице проверены выбор файла, пустая отправка, отклонение неверного MIME-типа, отображение имени и переход mock-загрузки через polling к `done`.
- Последовательность Tab: ссылка пропуска → выбор файла → отправка.
- Ожидание, результат с двумя событиями, отрицательный результат, ошибка и длинные тексты отрисованы на вымышленных props на ширинах 1440 и 375 px; горизонтального переполнения нет.
- Ошибка не содержит отрицательного вердикта; отрицательный результат не содержит карточек событий; время `44.2` отображается как `00:44.2`, `80` — как `01:20.0`.
- `reduced-motion` отключает анимацию; ошибок JavaScript в проверенном сценарии нет.

Скриншоты результатов используют только вымышленные данные. Это проверка представления, а не качества AI, реального API, юридической корректности событий или проигрывания MOV. Safari и настоящий сервер здесь не проверялись.

### Повторная ручная проверка

1. Выполнить `npm ci`, `npm run dev`, открыть страницу.
2. Проверить форму на широком экране и на ширине 375 px; пройти элементы клавишей Tab.
3. Отправить форму без файла, выбрать файл неподходящего типа: существующие предупреждения должны сохраниться.
4. Выбрать разрешённый тестовый `.mov`, проверить имя/размер и отправку. Дождаться результата заглушки.
5. Перед интеграцией проверить оба вердикта, ошибку и длинные тексты на вымышленных fixtures. Не помещать test-only переключатели в основной интерфейс.
6. Просмотреть diff: ожидаются только оформление в `web/` и документация.
