# Подключение интерфейса к API команды

Подключённая версия вынесена на `/connected`, её состояние управляется в `app/components/connected-home.tsx`. Главная `/` теперь предназначена только для просмотра дизайна, не вызывает API и не требует ключа. Это явный режим просмотра, а не автоматическая подмена при сбое API.

Ветка `feat/frontend-api` продолжает локальный этап дизайна `92eec3e`. Изменения ограничены `web/`. Python-файлы, алгоритм анализа и нормативный реестр не менялись. Публикация — отдельной веткой и pull request.

## Схема

Браузер → обработчик `/ui/api/*` в Next.js → API команды `/api/v1/*`.

Обработчик добавляет `X-API-Key` к запросам, в том числе к запросам HTML-плеера. Прямой доступ браузера к Python и настройка CORS не требуются. Это серверная часть фронтенд-проекта, а не изменение Python API.

| Действие | API команды |
|---|---|
| Проверка ключа | GET `/api/v1/jobs/{случайный UUID}`: ожидается 404 после авторизации; неверный ключ — 401 |
| Отправка | POST `/api/v1/analyze`, multipart-поле `file` |
| Опрос | GET `/api/v1/jobs/{id}/details` |
| Видео и перемотка | GET `/api/v1/jobs/{id}/video`, передача Range |

Ключ хранится в памяти сервера Next.js. Браузер получает случайную HttpOnly/SameSite cookie. Ключ не помещается в URL, localStorage или клиентскую конфигурацию. Для публичного доступа необходимо HTTPS. Ответы и видео имеют `Cache-Control: private, no-store`.

Сессии живут 8 часов и теряются при перезапуске Next.js. Поддерживается один процесс/экземпляр Next.js; для нескольких экземпляров потребуется общее хранилище сессий. В одной сессии хранятся последние 100 идентификаторов задач. Через новый интерфейс доступны только задачи, созданные в этой сессии. Это не меняет правила авторизации Python API.

## Поведение

- До отправки проверяются расширение `.mov`, ненулевой размер и лимит 100 MiB. Окончательную проверку выполняет API.
- Повторное нажатие не запускает вторую отправку. Автоматических повторов POST нет: при разрыве связи сервер мог уже принять файл.
- Опрос выполняется раз в 2 секунды без перекрытия запросов и прекращается при `done`/`failed`. При временной ошибке — до трёх попыток, далее ручной повтор статуса.
- После обновления страницы задача восстанавливается по `?job=...` при действующей сессии. Файл повторно не отправляется. Имя файла после обновления не сохраняется.
- Используются статусы `processing`, `done`, `failed`. Ошибка или некорректный ответ никогда не превращаются в `no_violation`.
- Плеер показывает исходную запись. Нажатие на время события или кадр переводит к указанной секунде. Фронтенд не определяет нарушения и не рисует вымышленные рамки на видео.
- JPEG-кадры и нормативное основание берутся из ответа сервера. Отсутствие источника обозначено явно. Ссылки разрешены только HTTP(S).
- Воспроизведение MOV зависит от кодека и браузера. При ошибке плеера описания и кадры остаются доступны. Транскодирование не добавлялось.
- «Новая проверка» возвращает к загрузке, но не отменяет принятую задачу: контракт не предоставляет отмену.

## Проверки

```sh
npm exec next build -- --webpack
npm exec eslint app/api.ts app/page.tsx app/components lib "app/ui/api/[...path]/route.ts"
node tests/integration.cjs
```

Последней команде нужны Playwright и установленный Edge. `PLAYWRIGHT_MODULE` позволяет указать путь к уже установленному модулю; production-зависимости не добавлялись. Тест поднимает искусственный API на `127.0.0.1:3201` и production Next.js на `127.0.0.1:3200`, затем закрывает их. Порты должны быть свободны. `QA_OUTPUT_DIR` позволяет сохранить снимки вне репозитория.

Проверено: production-сборка Webpack, TypeScript; браузерная цепочка вход → загрузка → опрос → результат; неверный ключ; чужой Origin; изоляция задач; JPEG-кадры; переход по таймкоду; Range 206/416; восстановление без повторной отправки; пустой результат; failed; некорректный контракт; выход; отсутствие горизонтального переполнения при 375 px. Исключений JavaScript в браузере нет.

Тест создаёт JPEG и WebM из canvas. Искусственный API принимает имя `.mov`, но отдаёт WebM: тест проверяет интерфейс и передачу видео, а не декодирование настоящего MOV. Конкурсные материалы не используются.

Общий lint сохраняет ранее существовавшую ошибку `prefer-const` в неиспользуемом `app/mock.ts`; этот файл не изменялся.

## Оставшаяся совместная проверка

Настоящий бэкенд ещё не запущен в этой среде. После получения адреса проверить вход с API-ключом команды, разрешённый тестовый MOV, реальный анализ, длительность и воспроизведение кодека в браузере. Эти результаты пока не подтверждены. Просмотр конкурсных материалов выполняют участники команды локально без отправки содержимого облачному AI.
